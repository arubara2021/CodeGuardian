## Phase 1 — Foundation

### What it built

The package identity, the error taxonomy, the retry engine, the redaction
walker, and the configuration system. Every later phase imports from
these modules.

### Deviations from BUILD_ORDER

1. Added `errors/translation.py` and `test_translation.py`. A leak probe found every standard library exception passed through untyped. The translation layer is the single place that converts them.
2. Added `FILE_PERMISSION_DENIED` to `codes.py`. `PermissionError` had no matching code.
3. Added `CONFIG_PARSE_ERROR` and `SECRET_KEYCHAIN_ERROR` to `codes.py`. Separates TOML syntax errors from schema errors, and keychain backend failures from schema errors.
4. Wrote seven Rust crate `Cargo.toml` stubs early. Empty workspace members broke `cargo metadata`.

## Phase 2 — Schemas

### What it built

Fourteen JSON Schema files, draft 2020-12, in the `schemas/` directory. Each describes one structured artifact that moves through the pipeline.

### The fourteen files

| File | Version | Describes |
|---|---|---|
| `schemas/cpg.json` | 1.0 | Code Property Graph metadata |
| `schemas/runtime-contract-map.json` | 1.0 | Runtime contract map |
| `schemas/recon.json` | 1.1 | Reconnaissance manifest |
| `schemas/blast-radius.json` | 1.0 | Blast Radius Report |
| `schemas/contract-assertions.json` | 1.0 | Caller contract assertions |
| `schemas/context-pack.json` | 1.1 | Context Pack sent to a model |
| `schemas/verification.json` | 1.1 | Verifier verdict |
| `schemas/plan-approval.json` | 1.0 | Plan approval record |
| `schemas/consent.json` | 1.0 | Apply consent record |
| `schemas/checkpoint.json` | 1.0 | Checkpoint state |
| `schemas/audit-entry.json` | 1.1 | One audit log entry |
| `schemas/plugin-manifest.json` | 1.1 | Plugin manifest |
| `schemas/skill.json` | 1.0 | Skill frontmatter |
| `schemas/run-summary.json` | 1.1 | Run summary |

### Structure of every schema

Every schema has:

- `$schema` set to `https://json-schema.org/draft/2020-12/schema`
- `$id` set to `https://codeguardian.dev/schemas/<name>/v<version>.json`
- `title`, `type`, `required`, `additionalProperties: false`, `properties`
- A top-level `extensions` property of type `object` with `additionalProperties: true`

Nested objects that have fixed keys also use `additionalProperties: false`. Nested objects that are intentionally open maps keep `additionalProperties` as a schema (for example, `hierarchical_index`, `versions.declared`, `edge_types`).

Selected nested objects also have an `extensions` property. These are the growth points the design had already exercised or the plugin architecture explicitly needs:

- `recon.structural`
- `verification.model`, `verification.findings[]`
- `audit-entry.input`, `.output`, `.blast_radius`, `.result`, `.verification`, `.consent`
- `plugin-manifest.language`, `.provider`, `.sandbox`, `.permissions`
- `run-summary.key_findings[]`, `.skill_proposals[]`

### Validation

Every schema validates against the draft 2020-12 meta-schema. The command used is:

```
python -c "
import json
import pathlib
from jsonschema import Draft202012Validator

schemas = sorted(pathlib.Path('schemas').glob('*.json'))
for path in schemas:
    with open(path) as fh:
        schema = json.load(fh)
    Draft202012Validator.check_schema(schema)
    print(f'OK   {path}')
"
```

### Deviations from docs/05-data-model.md

1. `additionalProperties: false` applied to every closed object. The design doc left this off. It catches typos and field drift at validation time. Authorized before Block B-014.
2. `extensions` field added at the top level of all fourteen schemas and on the specific nested objects listed above. Gives every schema a path for new fields without a version bump. Authorized before Block B-014 rewrite.
3. Tested per block instead of per phase. The phase-boundary triple test still ran as required.
4. Test command uses `Draft202012Validator.check_schema()` rather than `jsonschema.validate()` with a meta-schema argument.

## Phase 3 — Storage

### What it built

Six storage layers: a SQLite metadata index with WAL mode, a filesystem artifact store with schema validation on write, a binary Code Property Graph file manager with a defined header format, a two-tier cache, a migration runner, and a Markdown-backed skill library with FTS5 and vec0 indexes. Plus a retention sweep.

PRAGMAs applied on open:

```
PRAGMA journal_mode = WAL
PRAGMA synchronous = NORMAL
PRAGMA wal_autocheckpoint = 10000
PRAGMA mmap_size = 268435456
PRAGMA busy_timeout = 5000

```

### FilesystemStore

```python
class FilesystemStore:
    def __init__(self, root: Path, schemas_dir: Path) -> None: ...
    @property
    def root(self) -> Path: ...
    @property
    def schemas_dir(self) -> Path: ...
    def artifact_path(self, repo_id: str, run_id: str, filename: str) -> Path: ...
    def write_artifact(self, repo_id, run_id, filename, data, schema_filename) -> Path: ...
    def read_artifact(self, repo_id, run_id, filename) -> dict[str, Any]: ...
    def write_text(self, repo_id, run_id, filename, content) -> Path: ...
    def read_text(self, repo_id, run_id, filename) -> str: ...
    def delete_run(self, repo_id: str, run_id: str) -> None: ...
```

Every write validates `data` against the named schema before writing. On failure, raises `CodeGuardianError` with `STORAGE_SCHEMA_INVALID`. Schemas are cached in memory after first load.

Artifact path layout: `<root>/repos/<repo_id>/runs/<run_id>/<filename>`.

Writes use two-space indent, sorted keys, and UTF-8. Two runs writing the same data produce byte-identical files.

### CPGHeader and GraphStore

The CPG binary header format, version 1. Fixed 64 bytes, little-endian.

| Offset | Size | Field |
|---|---|---|
| 0 | 4 | magic, `b"CGCP"` |
| 4 | 2 | format_version, uint16, currently 1 |
| 6 | 2 | header_size, uint16, currently 64 |
| 8 | 4 | flags, uint32, bit 0 = incremental |
| 12 | 8 | node_count, uint64 |
| 20 | 8 | edge_count, uint64 |
| 28 | 8 | payload_offset, uint64 |
| 36 | 8 | payload_length, uint64 |
| 44 | 8 | payload_checksum, uint64 |
| 52 | 12 | reserved, zero in v1 |

### Cleanup

```python
@dataclass(frozen=True, slots=True)
class CleanupSummary:
    runs_swept: int
    run_files_deleted: int
    graph_files_deleted: int
    cache_entries_deleted: int

def run_cleanup(
    sqlite_store: SQLiteStore,
    filesystem_store: FilesystemStore,
```

Prunes run artifacts older than 30 days, graph files and cache payloads older than 90 days, and forces a WAL checkpoint if the WAL exceeds 100 MB. Audit logs, run summaries, plan approvals, and consent records are never pruned.

The files inside a run directory that are prunable:

```

contract_assertions.json
test_target.py
refactored_target.py
diff.patch
verification.json
checkpoint.json
```

`audit.jsonl` and `summary.md` are never pruned.

Skill files live at `<root>/skills/<name>/SKILL.md`. Each file has a YAML frontmatter block delimited by `---`, followed by Markdown body. Frontmatter is validated against `schemas/skill.json` on every write and every read.

Embedding dimension is 384. Embeddings are caller-provided. The store does not generate them.

FTS5 index (`skills_fts`) uses external content from the `skills` table. Sync is manual: an `INSERT INTO skills_fts(skills_fts, rowid, ...) VALUES ('delete', ...)` before each row replacement, followed by a new `INSERT INTO skills_fts(rowid, ...)`.

### Deviations from BUILD_ORDER and from docs/05-data-model.md

1. `migrations.py` renamed to `migration_runner.py`. A module and a package cannot share a name in the same parent package. The `migrations/` package holds the SQL files; the runner had to be renamed. `BUILD_ORDER.md` corrected to match.
2. Added three error codes: `STORAGE_MIGRATION_FAILED`, `STORAGE_SCHEMA_INVALID`, `STORAGE_GRAPH_CORRUPTED`. All categorized as SYSTEM. The latter two carry non-retryable overrides because retrying is pointless.
3. Added the `_schema_migrations` table. Not in the design doc. Every migration runner needs it. Created by `SQLiteStore.open()`.
4. Defined the CPG binary header format in Phase 3. The design doc says the file is binary but does not specify its layout. Phase 3 reads node and edge counts from the header. Phase 6 must write files that match byte for byte.
5. Real pytest files under `tests/` for the permanent suite. The inline per-block scripts were verification tools.
6. `contextlib.suppress` used in `sqlite_store.py` in two places instead of `try`/`except`/`pass`, to satisfy ruff's SIM105 rule.
